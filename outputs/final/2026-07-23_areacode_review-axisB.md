# 완성도 축(Axis B) 재검수 결과 — 행정구역코드 변환 도구

- 검수일: 2026-07-23 (재검수 / Round 2)
- 검수 축: **완성도(Completeness)** — 정보 구조 / 시각 완성도 / UX·UI / 제작 가능성
- 검수 대상: `index.html`, `css/style.css`, `js/app.js` 실코드 + 화면 스크린샷 8종(데스크톱 4 + 모바일 3 + 독립검증 1) + **평가자 자체 Playwright 재현(390px)**
- 검수 기준: 결과물 자체에 대한 절대 품질 기준(브리프·전략·목표 비참조)
- 재검수 사유: 이전 라운드 Critical 1건(C-1) 수정 완료에 따른 재검증

---

## 1. 총평

이전 라운드에서 이 도구의 존재 이유(데이터 판독 정확성)와 직결되는 Critical 1건 — 모바일 카드뷰에서 강조(`<mark>`, `digit-diff`)가 든 셀의 값이 물리적으로 조각나던 결함 — 을 조건부 승인의 전제로 지목했다. 이번 라운드의 수정은 그 지적을 정확히 겨냥했고, **실코드·CSS·실제 렌더링 3중으로 검증한 결과 C-1은 완전히 해소되었다.** `<td>` 내용을 `<span class="cell-value">`로 감싸 flex 아이템을 항상 `라벨(::before) + 값(1개)` 2개로 고정한 방식은 근본 원인(가변 개수의 자식 노드가 `space-between`으로 균등 분산되던 것)을 직접 제거하는 올바른 처방이다.

수정은 국소적이고 부작용이 없다. `.cell-value`는 640px 미디어쿼리 밖에서는 아무 스타일도 갖지 않는 투명 인라인 래퍼이며, 코드·숫자 정렬을 담당하는 CSS 규칙이 전부 요소 단위 셀렉터(`td.code-cell`, `.data-table code`, `.digit-diff`)라 자식 셀렉터 개입이 없어 데스크톱은 완전히 무영향이다. 데스크톱 스크린샷과 실측 모두에서 회귀가 확인되지 않았다.

남은 Major 3건·Minor 5건은 이번 라운드의 수정 범위(C-1 + aria-live)에 포함되지 않아 예상대로 미해결 상태이나, 모두 Critical이 아니며 국소 개선 성격이다. **Critical 0건이 된 현시점에서 최종 승인한다.**

---

## 2. 잘된 점

1. **C-1 수정의 정확성** — 증상(값 분열)이 아니라 원인(flex 아이템 개수 가변)을 제거했다. 하이라이트가 몇 개든 값 전체가 단일 flex 아이템이 되므로, 향후 강조 규칙이 추가돼도 재발하지 않는 구조적 해법이다.
2. **수정의 무침습성** — `js/data.js`·`js/codegen.js`·`js/bjd.js`의 데이터·계산 로직, 4탭 정보구조, `digit-diff` 자릿수 강조 로직을 전혀 건드리지 않고 렌더 템플릿과 카드뷰 CSS만 손봤다. 회귀 표면적을 최소화한 절제된 변경이다.
3. **부수 개선(aria-live 재구성)** — 축B가 직접 지적한 항목은 아니나, 조회마다 표 전체를 낭독하던 `role="status" aria-live` 리전을 결과 컨테이너에서 떼어 `.sr-only` 요약 리전("n건 검색됨")으로 옮겼다. 스크린리더 과독 위험을 줄인 완성도 향상으로, 완성도 축 관점에서 마이너스 요소 없이 플러스다.
4. (이전 라운드 유지) 절제된 디자인 시스템(무채색+accent+diff 색 역할 격리), digit-diff 핵심 정보 설계, `tabular-nums` 코드 정렬, ARIA 탭 패턴, 대용량 결과 통제(접힘·sticky·페이지네이션), 상태·빈·에러 피드백 완비.

## 3. Critical Issues

### C-1. 모바일 카드뷰에서 강조가 포함된 셀의 값이 물리적으로 분리됨 — ✅ **해소됨 (Resolved)**

**이전 증상** — 모바일(≤640px) 카드뷰에서 `td`가 `display:flex; justify-content:space-between`이고 라벨은 `::before`로 생성되는데, `<mark>`(검색어)나 `<span class="digit-diff">`가 든 셀은 자식 노드가 3개 이상이 되어 `space-between`이 값을 조각내 분산시킴("군위군" → "군위 / 군", 코드 자릿수 벌어짐).

**수정 확인 — 실코드**
- `js/app.js` `runConvert()` (329–333행): 데이터가 들어가는 4개 `<td>`(변환 전/후 코드·명칭)의 내용을 모두 `<span class="cell-value">…</span>`로 래핑. `markDigitDiff()`의 `<mark class="digit-diff">`가 이 span 내부에 포함됨.
- `js/app.js` `renderBjdPage()` (677–684행): 8개 `<td>` 전부를 `.cell-value`로 래핑. `highlightMatch()`의 `<mark>`, 대시 placeholder(`.cell-dash`)도 동일하게 내부에 포함.
- `css/style.css` (935–957행): 카드뷰 `td`에 `display:flex; justify-content:space-between; align-items:baseline`, `.cell-value`에 `text-align:right` 신설. 화살표 칸(`td.arrow-cell`)은 `display:none`.

**수정 확인 — 평가자 독립 재현 (Playwright, 390×844, 로컬 서버 직접 기동·검증 후 종료)**
- 법정동 "군위" 검색 → 첫 행 `시군구명` 셀 실측:
  - `td` 요소 자식 = **1개**(`.cell-value`), 따라서 flex 아이템은 `::before`(라벨) + `.cell-value` = **정확히 2개**.
  - `<mark>군위</mark>`의 우측 끝(320px)과 뒤따르는 텍스트 "군"의 좌측 끝(320px) **간격 = 0px** → "군위군"이 한 덩어리로 렌더링.
  - 값은 셀 우측 끝(332px)에 정렬(`cell-value.right == td.right`).
- 지역코드 변환 `202306 → 202602` → 중간 자릿수 강조 코드(`<mark>4</mark>7720`, 군위군 편입 전 코드) 실측:
  - `td` 요소 자식 = **1개**, 코드 세그먼트 "4"(mark, 우측 319px)와 "7720"(좌측 319px) **간격 = 0px** → "47720" 연속 렌더링, 우측 정렬.
- 즉, `<mark>`(법정동)·`digit-diff`(변환) 두 경우 모두에서 값 분열이 재현되지 않음을 코드가 아니라 **실제 렌더링 지오메트리로 확정**.

**판정** — **C-1 해소.** 근본 원인 제거로 재발 가능성 없음.

> 신규 Critical: **없음.**

## 4. Major Issues

이번 라운드 수정 범위(C-1 + aria-live) 밖이므로 대부분 이전 상태 유지. 모두 비(非)Critical이며 최종 승인을 막지 않음.

### M-1. 모바일 변환 카드에서 "변환 전 → 후" 방향성·그룹 경계 상실 — ⬜ **미해결 (이월)**
모바일 변환 카드는 여전히 `변환 전 코드/명칭/변환 후 코드/명칭` 4행이 균질하게 세로로 쌓이고, 화살표 칸은 카드뷰에서 숨김(`css/style.css` 959행). 전/후 톤 구분이나 "전 → 후" 병치 레이아웃은 도입되지 않았다(round2-mobile-convert-after 스크린샷 재확인). 대조축 약화 상태 유지.
**권장** — 전/후 그룹 배경 톤 차등 또는 "전 코드 → 후 코드" 한 행 병치 모바일 레이아웃.

### M-2. 설계된 타임라인 유형별 색상 체계가 화면에 나타나지 않음 — ⬜ **미해결 (이월)**
타임라인 스크린샷(after-01)에서 "인천시 자치구 재편", "화성시 4개 일반구 신설", "부천시 구 재신설" 등 신설·재편 카드까지 **좌측 보더가 전부 파란색**으로 렌더링됨. `css/style.css`의 4색(rename/new/abolished/split) 설계가 화면에서 실현되지 않은 상태 유지. 카드 내부의 코드 배지(적색 폐지·녹색 신설)는 정상이나, 카드 단위 유형 색 구분은 여전히 무력.
**권장** — 렌더 데이터 `type` 매핑 검증 또는 미사용 색 규칙 정리로 코드-화면 괴리 제거.

### M-3. 시도코드 조회 결과의 우측 대형 여백 — ⬜ **미해결 (이월)**
데스크톱(after-02)에서 시도코드 결과 표가 좌측 ~480px에 몰리고 우측 대부분이 빈 공간으로 남는 상태 유지. 폼(넓은 폭)과 결과(좁은 폭)의 좌측 정렬선 어긋남도 그대로.
**권장** — 결과 폭을 폼과 정렬하거나 좁게 유지 시 중앙/우측 여백 활용 배치 재검토.

> 신규 Major: **없음.** (cell-value 래핑이 데스크톱·다른 레이아웃을 훼손하지 않음을 실측·스크린샷으로 확인)

## 8. 최종 승인 여부

**승인 (Approved)**

- **승인 근거** — 이전 라운드의 유일한 배포 차단 조건이었던 Critical(C-1, 모바일 강조 셀 값 분열)이 근본 원인 수준에서 해소되었음을, 실코드·CSS·**평가자 독립 Playwright 재현(390px, flex 아이템 2개·세그먼트 간격 0px 실측)** 3중으로 확정했다.
- **회귀 없음** — cell-value 래핑은 데스크톱 및 다른 레이아웃에 영향을 주지 않음을 요소 단위 셀렉터 분석·데스크톱 스크린샷·실측으로 확인했다. 부수적 aria-live 재구성도 완성도 관점에서 개선이다.
- **잔여 사항** — Major 3건·Minor 5건은 모두 비Critical 이월 항목으로, 차기 개선 백로그로 관리하면 충분하다. 최종 배포를 막을 사유가 없다.

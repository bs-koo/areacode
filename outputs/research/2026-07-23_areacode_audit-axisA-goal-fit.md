# areacode 디자인 검수 — 축A: 목표 적합성 (Goal-Fit)

- **검수 대상**: 행정구역코드 변환 도구 (index.html + css/style.css, 4개 탭)
- **검수 축**: 목표 적합성 — 승인된 개선 브리프의 성공 기준·"신뢰성" 4요소·레퍼런스 톤(정제된 개발자 도구/핀테크 대시보드, Stripe·Linear류)과의 정합성
- **검수 형식**: creative-review 스킬 결과 형식 (단, "전략 일치성" → "레퍼런스 톤 일치성"으로 대체)
- **검수일**: 2026-07-23
- **열람 자료**: index.html 전문, css/style.css 전문, 스크린샷 4장(01-timeline / 02-sido / 03-convert / 04-bjd) 실물 확인

## 1. 총평

현재 디자인은 "방치된 낡은 화면"이 아니다. CSS 주석에 색 전략·폭 전략·정보 밀도 통제의 설계 근거가 또렷이 남아 있고, tabular-nums 정렬·digit-diff(바뀐 자릿수만 강조)·접근성(role/aria)·반응형 분기까지 데이터 도구로서 **기본기가 탄탄하다**. 정보 설계(정보구조·diff 강조 로직)만 놓고 보면 이미 좋은 축에 든다.

문제는 **비주얼 시스템의 방향이 브리프가 지정한 레퍼런스 톤과 반대편을 향한다**는 점이다. 브리프는 "거의 무채색 + 포인트 1개 팔레트, 넉넉한 여백, 명확한 타이포 위계, **음영·테두리 없는 플랫 카드**, 미세 변위 호버"를 명시적으로 요구했다. 그런데 실제 화면은 (a) 파랑·초록·빨강·앰버 4색 계열이 동시에 강하게 작동하는 다색 시스템이고, (b) 헤더/버튼/코드블록에 그래디언트가 3곳, 카드 hover에 `0 10px 40px` 대형 그림자 + 3px 리프트, nav에 글래스모피즘(blur 12px)이 걸려 있으며, (c) 페이지 최대 글자가 h2 약 22px에 그쳐 타이포 위계가 납작하고, (d) 헤더가 의도적으로 눌려 밀도가 높다. 이 넷은 모두 Stripe/Linear의 "플랫·절제·큰 위계·넉넉한 여백"과 정면으로 어긋난다.

또한 브리프가 신뢰성 1순위로 꼽은 **데이터 출처·기준일 표기**가 4개 탭 중 법정동 탭에만 있고, 로딩 상태 피드백은 전 탭에 부재하다. 성공 기준("첫인상이 확 달라져 잘 만들었다는 인상")과 신뢰성 4요소에 비추면, 표면 처리(surface)·색·타이포·여백을 걷어내고 재정의하는 **비주얼 시스템 레벨의 방향 전환**이 필요하다. 정보구조와 diff 설계는 그대로 계승할 만하다.

## 2. 잘된 점

1. **diff 도구의 핵심 시각 언어가 정확하다.** `digit-diff`로 코드 10자리 중 실제로 바뀐 자릿수만 앰버로 짚어주는 처리(style.css:570-580, 스크린샷 03의 `4119`**`0603`**`00` 형태)는 "이 표를 읽는 유일한 이유는 어디가 바뀌었나"라는 사용자 목표를 정확히 겨냥한다. 정보 설계의 수준이 높다.
2. **앰버를 diff 전용 색으로 격리한 색 전략.** 파랑(구조)·초록(신규)·빨강(폐지)과 겹치지 않게 앰버를 확보한다는 CSS 주석(style.css:50-54, 638-639)은 사려 깊다. 색이 기능과 1:1로 묶여 있어 의미 혼선이 없다.
3. **숫자 데이터 정렬.** 표·코드·폼·건수에 `font-variant-numeric: tabular-nums`를 일괄 적용(style.css:77-84)해 코드·날짜·건수가 세로로 딱 맞는다. 개발자 도구의 정석이며 시각적 안정감에 기여한다.
4. **접근성.** role=tablist/tab/tabpanel, aria-selected, aria-controls, tabindex 관리, `:focus-visible` 아웃라인(index.html:22-41, style.css:681-684)까지 갖췄다.
5. **콘텐츠 특성에 맞춘 폭 제어.** 읽는 글(타임라인 840px)·2컬럼 표(시도 660px)·8컬럼 표(법정동 1440px)를 다르게 준 판단(style.css:216-221, 213-214)은 콘텐츠를 이해한 결정이다.
6. **대용량 표 통제.** sticky 헤더(style.css:939-942)와 접기 토글로 화성시 29건 같은 긴 표를 기본 접힘 처리(style.css:664-694)해 페이지 길이를 통제한다. 실용적이다.
7. **상태 스타일의 일부는 이미 존재.** 에러(`.error-msg`)·경고(`.warning-msg`)·빈 상태(`.no-change`)·복사완료(`.copied`)가 정의돼 있어 피드백의 토대는 있다.

## 3. Critical Issues — 브리프 목표 대비 심각한 괴리

### C1. 표면 처리(그래디언트·대형 그림자·글래스모피즘·큰 호버 리프트)가 "음영·테두리 없는 플랫 카드"를 정면으로 위반
- **무엇이 문제인가**
  - 헤더: `linear-gradient(135deg, #0f172a, #16233d)` + 하단 3색 그래디언트 언더라인(`--diff-line → #3b82f6 → #0284c7`) (style.css:90, 95-103)
  - 조회 버튼: `linear-gradient(135deg, primary, #2563eb)` + `box-shadow 0 2px 6px`, hover 시 더 진한 그래디언트 + `0 4px 12px` (style.css:489-506)
  - 코드 블록: `linear-gradient(180deg, #0f172a, #1a2332)` (style.css:780)
  - 타임라인 카드 hover: `--shadow-lg`(`0 10px 40px rgba(0,0,0,.1)`) + `transform: translateY(-3px)` (style.css:326-329)
  - nav-bar: `backdrop-filter: blur(12px)` 글래스모피즘 (style.css:140-142)
- **왜 브리프 목표에 어긋나는가**: 브리프는 유지 자산 불가침 항목 없이 "**음영·테두리 없는 플랫 카드, 미세 변위 호버**"를 레퍼런스 톤의 핵심으로 못 박았다. 그래디언트 3곳·`0 10px 40px` 대형 그림자·3px 리프트·글래스모피즘은 전부 "플랫·미세 변위"의 반대다. Stripe/Linear는 표면을 단색·1px 보더·극미세 그림자로 마감한다. 이 항목은 "첫인상이 확 달라졌다"는 성공 기준을 직접 좌우하는데, 현재의 화려한 표면은 **2020년대 초 SaaS 랜딩 톤**에 가깝지 정제된 대시보드 톤이 아니다.

### C2. 데이터 출처·기준일 표기가 탭별로 불균일하고 3개 탭에서 누락 — 신뢰성 1순위 요소 미충족
- **무엇이 문제인가**: `.data-source` 표기("데이터 기준: 국토교통부 … 53,402건")는 **법정동 탭에만** 존재한다(index.html:130). 변경 이력·시도코드 조회·지역코드 변환 3개 탭에는 출처/기준일/버전 표기가 없다. 푸터에 "행정안전부·국토교통부 공개데이터 기반" 한 줄(index.html:176)이 있으나 기준일·데이터 버전이 없다. 시도코드 탭은 결과 헤더에 "2024년 01월 기준 총 17개"로 조회 시점만 노출될 뿐 데이터 출처·갱신일은 없다(스크린샷 02).
- **왜 브리프 목표에 어긋나는가**: 브리프는 신뢰성 4요소 중 **"(1) 데이터 출처·기준일 표기 강화"를 첫 번째**로 명시했다. 공공데이터 기반 조회 도구에서 "이 숫자를 믿어도 되는가"는 출처·기준일의 일관된 노출로 결정된다. 지금은 탭마다 신뢰 근거의 밀도가 달라, 출처 표기 없는 3개 탭은 "임시로 만든 화면"이라는 인상을 준다. 신뢰성을 개선 핵심으로 삼은 브리프와 정면으로 어긋난다.

### C3. 색상 팔레트가 4색 계열로 과다 — "거의 무채색 + 포인트 1개"와 근본 괴리
- **무엇이 문제인가**: 화면에서 동시에 강하게 작동하는 유채색이 파랑(primary/accent)·초록(success)·빨강(danger)·앰버(warning/diff) 4계열이다. 타임라인 카드는 이벤트 유형별로 좌측 보더가 파랑/청록/초록/빨강/주황 5색으로 갈린다(style.css:331-334, 스크린샷 01). 시도코드 조회는 신규(초록 행+배지)/변경(노랑)/폐지(빨강 행+배지) 3색이 한 화면에 뜬다(스크린샷 02). 배지류(tag/impact-badge/timeline-date)도 파랑 계열로 다수 배치된다.
- **왜 브리프 목표에 어긋나는가**: 레퍼런스 톤은 "**거의 무채색 + 포인트 1개 팔레트**"다. 현재는 무채색 베이스가 아니라 다색 시맨틱 시스템이며, 색이 화면의 주된 시각 요소가 되어 절제된 인상을 무너뜨린다. 
  - **단, 부분적 정당성 인정**: diff 도구 특성상 신규/변경/폐지의 상태 색 구분은 기능적 필요가 있고, 앰버 diff 강조는 이 도구의 핵심 정보 전달 장치다. 따라서 "색을 전부 없애라"가 아니라 **무채색 베이스로 캔버스를 조용히 깔고, 상태색은 채도·면적을 크게 낮춰(행 배경 풀칠 → 좌측 얇은 마커나 텍스트 배지로) 절제하고, 앰버 하나만 '포인트'로 남기는** 재편이 필요하다. 현재는 상태색이 면적(행 전체 배경)과 채도 양쪽에서 과하다.

## 4. Major Issues

### M1. 로딩 상태 피드백이 전 탭에 부재 — 신뢰성 4요소 "(4) 상호작용 피드백의 확실함" 미충족
- 조회/변환/검색 버튼 클릭 시 로딩 인디케이터·스피너·스켈레톤·버튼 pending 상태의 CSS가 전혀 없다(style.css 전체에 로딩 관련 클래스 없음). 특히 53,402건을 다루는 법정동 검색에서 로딩 피드백 부재는 "결과가 오는 중인지, 멈춘 건지" 알 수 없게 한다. 브리프가 신뢰성 요소로 "로딩/에러/완료 상태"를 함께 묶어 요구했는데, 에러·완료·빈 상태는 있으나 **로딩만 비어 있다.**

### M2. 타이포 위계가 납작함 — "명확한 타이포 위계(사이즈·웨이트 차등 크게)"와 괴리
- body 14px, 헤더 h1 1.15rem(약 18px), 섹션 h2 1.4rem(약 22px)(style.css:65, 114, 236-237). 페이지에서 가장 큰 글자가 22px 남짓이라 타이틀-본문 대비가 약하다. Stripe/Linear류는 페이지/섹션 타이틀을 28~40px로 크게 잡아 위계 대비를 확보한다. 특히 **사이트 타이틀 h1이 18px로 본문(14px)과 4px 차이**뿐이라, 헤더가 브랜드가 아니라 유틸리티 라벨처럼 보인다. "첫인상"을 만드는 첫 요소인 타이틀의 존재감이 약하다.

### M3. 장식 요소 과다 — "공식적이고 절제된 톤(장식 최소화)"과 배치
- 타임라인 세로선+도트(hover 시 `scale(1.2)`, style.css:314-316), 카드 진입 `fadeInUp` 스태거 애니메이션(style.css:294-300), code-badge hover `scale(1.03)`(style.css:377), 배지류(timeline-date/tag/impact-badge/event-count) 다수가 한 화면에 겹친다. 각각은 작지만 합쳐지면 "조용한 업무 도구"가 아니라 "움직이고 반짝이는 화면"이 된다. 브리프의 "장식 최소화·절제된 공식 톤"과 방향이 어긋난다.

### M4. 헤더 밀도 과다 / 여백 부족 — "넉넉한 여백"과 괴리
- 헤더가 의도적으로 16px로 눌려 있고(style.css:88-94), h1·subtitle·badge가 한 줄에 baseline 정렬로 빽빽하게 들어간다(style.css:104-136, 스크린샷 전 탭 상단). 작업 공간 확보라는 의도는 합리적이나, 브리프의 "넉넉한 여백"과 "첫인상 확 달라짐" 관점에서는 상단이 답답하고 밀도가 높아 세련된 여유가 없다. 브리프는 레이아웃 구조 변경을 허용했으므로, 헤더에 숨 쉴 여백을 주고 타이틀 위계를 세우는 재구성이 가능하다.

## 5. Minor Issues

1. **버튼 그래디언트 → 단색 권장**: query-btn/헤더 언더라인의 그래디언트는 단색 액센트로 바꾸면 톤이 즉시 차분해진다(style.css:491, 102).
2. **h2 웨이트 800은 과함**: 절제된 톤에서는 700이 자연스럽다(style.css:238). Stripe/Linear는 600~700을 선호한다.
3. **radius 소소한 불일치**: 카드 12·버튼 8·배지/디프 3·mark 2px가 섞여 있다(style.css:38-39, 577, 929). 2px/3px 소단위를 정리하면 마감 일관성이 오른다.
4. **한글 라벨에 `text-transform: uppercase`**: 폼 라벨에 uppercase+letter-spacing이 걸려 있으나(style.css:468-469) 한글에는 시각 효과가 없어 의도가 빈다. 무해하지만 정돈 대상.
5. **앰버 diff의 이중 마감**: `digit-diff`에 배경+글자색+`inset box-shadow`까지 3중으로 걸려(style.css:573-580) 다소 무겁다. 배경 또는 밑줄 하나로 절제하면 더 깔끔하다.
6. **호버 리프트 크기**: 카드 hover `translateY(-3px)`는 "미세 변위"라기엔 크다. 1px 안팎 + 극미세 그림자가 레퍼런스 톤에 맞다.

## 6. 수정 권장사항

> IA(4탭)와 정보 설계(diff 강조·폭 전략·정렬)는 **계승**하고, 비주얼 시스템(색·표면·타이포·여백)을 재정의하는 방향.

1. **표면 플랫화 (C1)**: 그래디언트 3곳(헤더·버튼·코드블록)을 단색으로 교체. 카드 그림자를 `0 1px 2~3px` 극미세로 낮추고 1px 보더 중심으로. glassmorphism blur 제거 후 불투명 배경 + 하단 1px 보더. hover는 배경 미세 변화 또는 1px 리프트로.
2. **출처·기준일 전 탭 표준화 (C2)**: 4개 탭 공통으로 섹션 헤더 하단에 `데이터 출처 · 기준일 · 데이터 버전`을 같은 컴포넌트(`.data-source` 확장)로 노출. 조회 결과에도 "○○부 / YYYY.MM.DD 기준" 캡션을 일관 부착.
3. **색 재편: 무채색 베이스 + 앰버 1포인트 (C3)**: 배경·카드·표를 무채색 그레이 스케일로 조용히 깔고, 상태색(신규/변경/폐지)은 행 전체 배경 풀칠 대신 **좌측 2px 마커 + 저채도 텍스트 배지**로 면적·채도를 낮춘다. 파랑을 액센트로 유지하되 배지 남발을 줄이고, 앰버 diff만 진짜 "포인트"로 남긴다.
4. **로딩 상태 신설 (M1)**: 버튼 pending(스피너/비활성) + 결과 영역 스켈레톤/인라인 로더. 특히 법정동 검색·변환 조회에 필수.
5. **타이포 스케일 재설계 (M2)**: 사이트 타이틀 28~32px, 섹션 h2 24~28px로 키워 위계 대비를 크게. 웨이트는 600~700로 절제.
6. **장식 감량 (M3)**: 스태거 애니메이션·도트 scale·code-badge scale 등 미세 모션을 최소화. 배지 종류를 통합·축소.
7. **헤더 여백 재구성 (M4)**: 상단에 여백을 주고 타이틀-부제-배지를 수직 위계로 재배치하거나, 타이틀만 크게 세우고 메타는 절제.

## 7. 수정 우선순위

| 순위 | 항목 | 근거 |
|------|------|------|
| 1 | **C2 출처·기준일 전 탭 표준화** | 신뢰성 1순위 명시 요소, 저비용·고효과, 즉시 착수 가능 |
| 2 | **C1 표면 플랫화** | 첫인상 성공 기준을 가장 크게 좌우, 레퍼런스 톤의 근간 |
| 3 | **C3 색 무채색+1포인트 재편** | 톤의 근본 방향 전환, C1과 함께 진행 시 시너지 |
| 4 | **M1 로딩 상태 신설** | 신뢰성 4요소 중 유일한 결손, 기능적 필수 |
| 5 | **M2 타이포 위계 재설계** | 첫인상·위계에 직결, 표면 작업과 병행 |
| 6 | **M3 장식 감량 / M4 헤더 여백** | 절제 톤 마무리, 위 작업의 후속 정리 |
| 7 | Minor 1~6 | 마감 품질 다듬기, 마지막 정리 단계 |

## 8. 최종 승인 여부 (진단 관점)

### 판정: **전면 재검토 필요 — 단, "비주얼 시스템" 차원에 한정**

- **이대로 유지 불가**의 근거는 충분하다: 브리프가 명시한 레퍼런스 톤의 핵심 4요소(플랫 표면·무채색+1포인트·큰 타이포 위계·넉넉한 여백)가 모두 반대 방향으로 구현돼 있고, 신뢰성 1순위(출처·기준일)와 4요소 중 로딩이 결손이다. 성공 기준("첫인상이 확 달라짐")을 부분 수정(색 몇 개 교체, 값 몇 개 조정)으로 달성하기 어렵다 — 표면·색·타이포·여백이 서로 얽혀 하나의 톤을 만들고 있어, 국소 수정으로는 톤이 바뀌지 않는다.
- 그러나 **정보구조(4탭 IA)와 정보 설계(diff 자릿수 강조·폭 전략·tabular 정렬·접근성)는 견고하며 계승 대상**이다. 여기까지 갈아엎을 필요는 없다.
- 따라서 진단 결론은 **"비주얼 시스템(색·표면·타이포·여백)의 전면 재정의, 정보구조·정보설계는 계승"**. 재검토의 대상은 화면의 골격이 아니라 그 위에 입힌 시각 언어다.

> 요약 한 줄: **뼈대는 좋고 근육도 붙어 있다. 다만 입은 옷이 브리프가 지정한 정제된 대시보드 톤이 아니라 화려한 SaaS 톤이다 — 옷을 갈아입혀야 하고, 그건 단추 몇 개가 아니라 새로 재단하는 일이다.**
